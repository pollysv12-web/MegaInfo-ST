# MegaInfo — сводка проекта для продолжения работы

Документ, чтобы новая сессия (или другой разработчик) могла продолжить без старого чата.
Состояние на 11.11.2026, версия **0.2.1**.

## 1. Кто и что

- Владелец: пользователь GitHub `pollysv12-web`, новичок в коде и GitHub. Общение на русском.
  Обычно играет за парней — важно для местоимений («о нём»).
- Цель: одно расширение SillyTavern вместо россыпи скриптов, тоглов и регулярок для инфоблоков.
- Репозиторий: `pollysv12-web/MegaInfo-ST`. Рабочая ветка: **`claude/tender-mayer-gfobei`**,
  в `main` пока не слито, PR не создавался.
- Установка: Расширения → Install extension → `https://github.com/pollysv12-web/MegaInfo-ST`,
  в поле *Branch* указать `claude/tender-mayer-gfobei`.

## 2. Таверна пользователя

- Тестовый персонаж: **Кристофер**.
- Модель: `google/gemini-4-argon` через OpenRouter (API `openai`), стриминг включён.

## 4. Исходные пожелания (v0.1–0.2)

1. Скрипты Кисы: sims (финансы по каждой трате, потребности не скачут, показывать MBTI/д/р), дневник
   (не исчезает, не укорачивается, настраиваемые длина/детальность/NPC/слухи, «о нём», а не всегда «о ней»),
   лёгкий sims (дата, время, локация), вкладка NPC, очистка блоков без регулярок, несколько CSS-тем плюс тема «как в таверне».
2. Инфоблок пресета Wild Tourist 8.0.1: карточки персонажей, шкала отношений −100…100, мысли, напряжение 0–100
   (+1 активная сцена / +3 спокойная, на 100 — твист и сброс), сюжет и прогресс, расписание, 3–4 слуха.
   Без случайных скачков.
3. Блок локации: подробное описание только при смене места.
4. Шкала слоуберна со стадиями, которую отслеживают и модель, и бот.
5. Следы на теле (травмы, засосы, синяки, метки): не исчезают сами, реалистично заживают, видны, только если
   не прикрыты одеждой, мелочи не вызывают драмы.
6. Телефон Кисы: только когда им пользуются и если телефоны есть по лору, стиль не случайный.
7. Тогл HTML-карточек (реалистичные посты, документы и т. п.).

Общее: гибкость (длина, глубина, стиль, частота, вкл/выкл блоков), никакого «невидимого» контекста,
сохранение логов.

## 5. Архитектура (что сделано)

Протокол: модель пишет **один JSON** в `<megainfo>…</megainfo>` (события, не итоги) и, при необходимости,
`<megainfo_html>` для карточки. Код вырезает блоки из текста, хранит данные в `message.extra.megainfo`
(на каждый свайп своя копия через `swipe_info`), пересчитывает числа и рисует панель.

```
manifest.json          generate_interceptor: megaInfoInterceptor
index.js               события ST, перехватчик (чистит историю копиями, вставляет инструкцию), отрисовка, кнопки
src/settings.js        DEFAULTS, миграция v0.1, переопределения на чат (chat_metadata), местоимение по персоне
src/tracker.js         что просить (computeDue/inlineRequestFor), разбор ответа, отдельный запрос и повтор
src/request.js         sideRequest (всегда заканчивается сообщением user), chatHistory, cardContext, профили
src/render.js          панель: шапка + вкладки/стопка; карточка в Shadow DOM через DOMPurify
src/store.js           данные в сообщениях, места в chatMetadata.megainfo.places, placeTries
src/log.js             журнал диагностики (переживает перезагрузку, localStorage megainfo_log), отчёт
src/export.js          логи JSON, логи Markdown (с отладкой по сообщениям), дневник
src/quick.js           кнопка в меню «палочки»: вкл/выкл модулей глобально и для чата
src/ui-settings.js     панель настроек, «Что видит модель», места чата, счётчик токенов
src/core/engine.js     сборка инструкции, extractBlocks (+ голый JSON без тега), applyData, carryOver
src/core/people.js     сцена, спад статов, люди, деньги по транзакциям, симпатия (шаг ≤ maxStep)
src/core/slowburn.js   10 стадий, скорость, не больше стадии за игровой день, строгий режим
src/core/world.js      напряжение/твист, сюжет, расписание (абсолютное время), слухи (id rN, лимит)
src/core/marks.js      виды следов, тяжесть, длительность заживления, стадии, удаление зажившего
src/core/location.js   описание места один раз, поиск по похожему названию
src/core/extras.js     дневник, телефон, HTML-карточки (правила и разбор)
style.css              темы tavern/glass/noir/parchment/pastel/minimal/custom, мобильная вёрстка
settings.html          настройки (все пути data-mi-setting проверены против DEFAULTS)
```

Ключевые решения:
- Режимы: `auto` (в ответе, при ошибке — отдельный запрос), `inline`, `separate`. Отдельный запрос:
  `light` (последние N сообщений) или `full` (60 сообщений с ролями + описание персонажа/персоны).
  Сделан через `generateRaw`/Connection Manager, **не** через `generateQuietPrompt`.
- Инструкция по умолчанию вставляется как **user**, depth 0 (Gemini/Claude поднимают system наверх).
- Частота у каждого модуля («каждые N ответов»), между обновлениями — только напоминание о состоянии.
- Ожидание в перехватчике — только за отдельными запросами, которые пересчитывают числа (дневник не блокирует), до 20 с.
- Свайп/перегенерация: данные расширения очищаются (ST сам `extra` не чистит).
- Оборванный блок в `auto` не применяется частично — добирается отдельным запросом.
- Заглушки из примера («…», «Имя NPC») отбрасываются; время назад не идёт.

## 6. Найденные причины багов

- v0.1, «блок один раз и пропал»: тег `<sims>` совпадал со скриптами/регулярками Кисы; регулярки AI_OUTPUT без
  promptOnly/markdownOnly режут ответ до `MESSAGE_RECEIVED`; при свайпе наследовалось старое состояние;
  оборванный блок применялся частично.
- Скрипты Кисы ломаются через 3–10 сообщений, потому что после первого блока шлют короткий update-промпт без формата.
- 0.2.0, `Bad Request`: `generateQuietPrompt` кладёт инструкцию system-сообщением в конец, OpenRouter поднимает
  system наверх → запрос кончается репликой assistant → Gemini 400. Исправлено в 0.2.1.
- Совместимость: старые `generateRaw`/`generateQuietPrompt` позиционные — проверка по `fn.length >= 2`.

## 8. Бэклог v3 (запрос пользователя от 11.11.2026, НЕ начат)

1. **Карточки и телефон внутри ответа**, а не приклеенные к инфоблоку: появляются в том месте текста, где персонаж
   пользуется телефоном или появляется предмет. Вероятный путь: модель ставит маркер в тексте (например
   `<megainfo_phone/>` или `[[mi:phone]]`), код подставляет на его место отрисованный блок (данные по-прежнему
   в `extra`, из истории для модели вырезать).
2. **Следы на теле**:
   - настройка, учитывать ли тату, пирсинг и прочие постоянные метки (новое тату — да, врождённое/исходное — нет);
   - больше реализма и видов: пулевое, ножевое, ожог, обморожение, окрашенная кожа (краска, хна, загар,
     покраснение) и т. п.; интересное и редкое появление;
   - настраиваемая скорость заживления (быстрая / реалистичная / долгая, возможно по типам);
   - кнопка в инфоблоке, чтобы убрать след вручную.
3. **Слоуберн сильнее влияет на игру** + настройка силы влияния (слабо / средне / сильно).
4. **Дни рождения**: дата генерируется автоматически; когда в игре наступает день рождения юзера или бота,
   окружающие (или самые близкие) об этом знают, без «у тебя завтра день рождения» заранее.
5. **Потребности заметнее**, но органично:
   - гигиена < 25%, голод ~10–20%, сильная усталость — окружающие замечают без драмы,
     реагируют только если это в характере;
   - возбуждение должно и падать, а не только расти: разделить бытовое (азарт, радость) и сексуальное;
     на поведение влияет только высокий порог;
   - при голоде или усталости около 0 — обморок.
6. **Свёрнутость панели запоминается** после перезагрузки чата (сейчас `collapsedOverride` в памяти —
   хранить в `extra` или `chatMetadata`).
7. **Дневник**: настройка «в начале / в конце ответа» и чтобы он реально появлялся сразу после ответа
   (сейчас пишется отдельным запросом позже и живёт во вкладке).
8. **Отношения**: плашка «бот ↔ юзер» выше, чем NPC.
9. **MBTI**: короткая подпись («Делец»), подробное описание характера по наведению или тапу.
10. **Одежда**: учитывать частичные изменения (снял куртку, надел шарф) — сейчас подхватывается хорошо,
    в том числе из расширения гардероба по картинке.
11. **Мысли юзера**: галочка, чтобы в состоянии писались и мысли {{user}} (для тех, кто даёт боту играть за себя).
12. Самому потыкать таверну и оптимизировать блоки в целом.
13. Проанализировать присланный лог долгой игры: `megainfo_…_2026-10-2611h40m00s510ms.json`, 273 КБ,
    53 сообщения, 0.2.1. Файл загрузки лежит во временной папке сессии — при новой сессии его нужно прислать заново.
