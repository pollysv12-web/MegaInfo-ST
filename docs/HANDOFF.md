# MegaInfo — сведения для продолжения работы

## Текущее направление: 0.3.1

Сводка обновлена **12 ноября 2026 года**. Код готовится как **MegaInfo 0.3.1**
в рабочей ветке **`claude/tender-mayer-gfobei`**. В неё включён вариант оформления
`test-UI` (база `1b7a2a5`); отдельное имя `0.3.0-ui.1` больше не является текущей
версией. Целевая метка выпуска — **`v0.3.1`**. Наличие коммита, тега и их отправку
на GitHub проверять по Git, не выводить из текста этой сводки.

Репозиторий: `pollysv12-web/MegaInfo-ST`. Ветка `main` содержит раннюю версию;
её не считать автоматически обновлённой после отправки рабочей ветки.
Установка: **Расширения → Install extension**, URL репозитория,
поле **Branch** — `claude/tender-mayer-gfobei`; точный выпуск — тег `v0.3.1`.

Пользователь просит общаться по-русски, простыми словами и доводить работу до
проверяемого результата. Новая просьба включает отправку 0.3.1 на GitHub.
Публикация облачной среды — отдельное действие; выпуск расширения её не требует.

## Изменения 0.3.1

- Розовые и красные акценты вместо жёлтых; название **Slow burn**.
- **Возбуждение** в UI — эмоциональная энергия; **Страсть** — сексуальное
  возбуждение. Для совместимости `person.excitement` остаётся эмоциональным,
  `person.stats.arousal` — сексуальным. Не переинтерпретировать прежние значения.
- `person.changes[field]` хранит причины изменений за текущий ответ:
  `{kind, from, to, delta, reason}`. `kind`: `time|event|initial|manual`.
  Используются фактические изменения после ограничений, включая дробный спад.
  `entry.reasons[field]` даёт причину события; при отсутствии причина не выдумывается.
  Транзакции используют `money[].note`. При переносе состояния на новый ответ
  прежние изменения очищаются, чтобы старые причины не выдавались за новые.
- В Пульсе есть раскрываемые пояснения чисел и маленькие кнопки редактирования
  числовых и текстовых полей. Ручная правка меняет текущий ответ и активный свайп;
  уже существующие последующие ответы не пересчитываются. Новый ответ исходит
  из актуального последнего состояния.
- Компактная панель **Вид / Персонажи / Наборы**. Внешний вид вынесен во вкладки;
  остальные настройки модулей остаются раскрывающимися разделами.
- Наборы: Повседневность, Медленный роман, Интриги, Только самое нужное,
  Саспенс, Быстрая страсть. Применяются явной кнопкой, меняют игровые настройки,
  сохраняют подключения, тему и данные чатов.
- Настраиваются порядок вкладок, показ полей Пульса `show|collapse|hide`,
  размер текста и контрастность.
- Выбор подробности по ролям, закреплённый NPC и персональные поля влияет
  на инструкции, применение данных и показ. Отключение не стирает историю.
- Сюжетные нити хранят открытые обещания и вопросы, необязательные возможные
  завершения. По умолчанию до шести активных нитей; их можно удалить вручную.
- Кармашек хранит только значимые вещи при человеке. По умолчанию до пяти;
  автоматический режим не должен заполнять квоту выдуманными вещами.
  Добавление, изменение, удаление и полностью ручное ведение доступны в UI.

## Протокол и хранение

Главный payload — JSON в `<megainfo>…</megainfo>`. HTML-карточка при необходимости
передаётся в `<megainfo_html>…</megainfo_html>`. Внутри рассказа остаются точки
вставки `[[mi:phone]]` и `[[mi:card]]`; `src/inline.js` заменяет их только в DOM.
Повторная отрисовка использует `.mi-slot` и не дублирует вставки.
Теги и маркеры удаляются из истории перед отправкой модели. В отдельном запросе
запрещены новые сюжетные действия и маркеры размещения.

`message.extra.megainfo` содержит `state`, `diary`, `phone`, `card`, `ui`,
диагностику и при необходимости `manualPulse`. Активный свайп синхронизируется
с `swipe_info[swipe_id].extra.megainfo`.

Основные поля состояния:

```text
state.people[id]            профиль, потребности, настроение, одежда, мысли,
                            деньги, симпатия, excitement, changes
state.marks                 следы и их заживление
state.world                 сюжет, напряжение, расписание, слухи
state.world.threads         [{id, text, endings: [...], date}]
state.pockets[personId]      [{id, name, note, at, manual?}]
```

Новые события модели:

```text
people[].reasons            {food: "причина", arousal: "причина", excitement: "причина", ...}
world.thread_add            [{text, endings: [...]}]
world.thread_drop           [id]
world.thread_update         обновление существующей нити
pocket.add                  [{who, name, note}]
pocket.drop                 [{who, id}]
pocket.update               [{who, id, name?, note?}]
```

Отсутствующий ключ коллекции не очищает её. Владельцы вещей разрешаются по
известным людям и точным именам, чтобы NPC с одинаковым первым именем не менялись
вещами. Повторное приобретение позже отличают время и стабильный id.

Метаданные чата `chatMetadata.megainfo`:

- `places` и `placeTries` — описанные места и ограничение повторных запросов.
- `overrides` — настройки модулей, наличие телефонов и местоимение текущего чата.
- `dismissedMarks` — защита от возврата вручную удалённых следов.
- `pocketEdits` и `dismissedThreads` — ручные изменения коллекций с границей
  `fromMessage`; прежние исторические сообщения не переписываются раньше неё.

`filterManualCollections(state, messageId)` применяется при сохранении результата
модели. `reapplyPulseEdits(message, state)` восстанавливает явные правки текущего
ответа после запоздавшего отдельного запроса. При новом свайпе прежние данные
этого ответа очищаются; соседние свайпы не должны получать его ручные правки.

Свёрнутость основной панели — `ui.collapsed`, открытые `<details>` — `ui.details`.
Телефон, карточки и заметки принадлежат ответу и не исчезают из старых сообщений
из-за `showOnLast`, который ограничивает основную панель.

## Настройки и совместимость

Версия настроек — **`schemaVersion: 4`**. Миграция прежней положительной скорости
пассивного сексуального возбуждения применяется только к старым схемам до 3;
обновление 3 → 4 сохраняет выбранные значения. Старые настройки v0.1 также
переносятся. Новые поля заполняются значениями по умолчанию без сброса существующих.

`settings.display` хранит `fontSize`, `contrast`, `tabOrder`, `pulse`,
`editControls`. Контраст: `normal|high|soft`; поля Пульса: `show|collapse|hide`.
`settings.tracking` хранит роли `char|user|npc`, `pinnedNpc` и `overrides` по
нормализованному имени. Единая функция `trackingFor(person, settings)` возвращает
`{detail, fields}`; подробность — `full|short|off`. Поля: `stats`, `mood`, `outfit`,
`thought`, `money`, `profile`, `relations`, `pocket`.

`modules.pocket`: `enabled`, `every`, `auto`, `maxItems` (по умолчанию 5).
`modules.world.threads`: включение нитей; `threadLimit` по умолчанию 6.
При `pocket.auto === false` модель не меняет кармашек.

Режимы `auto|inline|separate`, отдельные запросы `light|full`, роль инструкции
`user` на depth 0 сохранены. Последнее сообщение отдельного запроса — `user`,
что устраняет прежнюю проблему Gemini через OpenRouter. Полный контекст включает
до 60 последних сообщений и описания персонажа и персоны.

## Проверки и границы подтверждения

```sh
npm ci --ignore-scripts
npm test
npm run test:browser
npm run test:browser:v31
```

Для браузерного стенда нужен Chromium; `MEGAINFO_CHROMIUM_PATH` задаёт путь.
Стенд воспроизводит события ST и ответы модели на макете. Реальная локальная
таверна проверяется отдельно: загрузка версии, данные тестового ответа, вкладки,
ручные правки, кармашек, нити, перезагрузка и мобильная ширина.

В этой работе пользователь уточнил, что требуется **тестовая таверна в облачной
среде**, а не внешний сервер. Не обращаться к личным чатам и не выводить
проверку личной установленной таверны из локального результата.
Без настроенного провайдера используются подготовленные ответы; это проверяет
интерфейс и обработку данных, но не качество генерации выбранной моделью.
Снимок облачной среды не сохраняет живые процессы: локальный хост запускается
по сохранённым инструкциям в каждой задаче.

Проверки 0.3.1 в этой работе: **95/95 unit**, **106/106 прежних браузерных сценариев**,
**27/27 новых браузерных сценариев**, **45/45 проверок настоящего локального
SillyTavern 1.19.0** с подготовленным ответом (без вызова модели). Проверены
карандашики, раскрытие причин, операции с вещами, удаление нити, темы, мобильная
ширина и сохранение после перезагрузки. Независимая проверка панели при 320 px
и размере текста 125% не нашла переполнения. Необязательные запросы ненастроенного
Horde возвращали HTTP 500; это не проверка работоспособности провайдера.

Исторические
59/59 unit и 106/106 браузерных относились к 0.3.0 и 0.3.0-ui.1; они не являются
подтверждением новых функций. Исторические 88/88 относились к 0.2.1.

## Исторические причины ошибок

- Удаляющие служебные теги регулярки и дублирующие скрипты могли съедать блок
  до `MESSAGE_RECEIVED` или отправлять модели противоречивые инструкции.
- При свайпе и перегенерации ST мог оставлять `extra` прежнего ответа;
  перед новым применением свои данные нужно очищать.
- `generateQuietPrompt` и перенос system-сообщений приводили к финальной роли
  assistant и Gemini 400; отдельный запрос использует финальную роль user.
- Оборванный JSON в `auto` добирается отдельным запросом. Частично разбирать его
  вместо восстановления не следует; исключение — явно выбранный inline-режим.
- Старые дневники и карточки могли присутствовать в данных, но теряться при показе.
  Наличие сохранённых данных и видимость UI проверяются отдельно.
- До 0.3.0 сексуальное возбуждение могло расти пассивно по старому +10/2 часа;
  это историческое поведение, а не изменение семантики в 0.3.1.

Личные экспортированные логи не хранить в публичном репозитории и не цитировать
в технической сводке. Старые данные о доступе к серверу, модели или подключении
не доказывают текущую авторизацию. Секреты запрашиваются только через защищённые
настройки, не в чате.
